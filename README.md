# ProcessEngine 流程编排平台

> 基于 **Java 21 + Spring Cloud 微服务** 与 **Vue 3** 的通用型流程编排平台。
> 一套引擎同时支撑三类场景：**审批工作流**、**任务/服务编排**、**数据与系统集成**。

执行内核为**自研轻量令牌驱动引擎**，采用 BPMN 风格建模（JSON 为主模型，BPMN 2.0 XML 作为导入导出适配格式）。

## 平台定位

```
                 ┌─────────────────────────────────────────────┐
                 │         ProcessEngine 流程编排平台           │
                 ├──────────────┬──────────────┬───────────────┤
                 │   审批工作流   │   任务/服务编排  │  数据/系统集成  │
                 │  会签 · 加签   │  并行 · 重试    │  HTTP · SQL   │
                 │  转办 · 撤回   │  补偿 · 定时    │  MQ · 脚本     │
                 └──────────────┴──────────────┴───────────────┘
                                     ▲
                        一套令牌驱动执行内核 + 一套建模/表单/调度/集成能力
```

与常见方案的差异：

| 对比对象 | 差异 |
| --- | --- |
| Flowable / Camunda | 自研内核，人任务与自动化节点同构；实例级串行 + 无状态 worker，天然贴合云原生水平扩展；不背负 BPMN 全量语义的历史包袱 |
| 纯低代码平台 | 引擎语义完整（网关、子流程、补偿、故障干预），不是「表单 + 审批」的简化版 |
| ETL / 调度工具（Airflow、XXL-Job） | 原生支持人工节点、会签、撤回等审批语义，同时支持 DAG 式的数据编排 |
| iPaaS / 集成平台 | 内置完整流程建模与人机交互能力，连接器只是能力之一 |

## 三条设计主线

1. **令牌驱动**——实例是一张图，`Token` 是执行指针。遇到等待态就停下落库，被唤醒后从统一的推进指令继续。所有唤醒路径收敛为一条，便于排查与恢复。
2. **不用分布式事务**——跨服务一致性 = 本地事务 + Outbox + 幂等消费 + 补偿 + 三层对账。**Redis 不是正确性依赖**，它故障时引擎降级运行而不产生数据错乱。
3. **引擎语义可单测**——`engine-core` 对 Web 与 ORM 零依赖，持久化通过仓储接口反转，节点行为通过 SPI 注册。新增节点类型不改内核代码。
