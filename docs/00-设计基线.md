## 1. 术语表（Glossary）

| 术语 | 英文/标识 | 定义 |
| --- | --- | --- |
| 流程定义 | Process Definition (`pf_process_def`) | 一个流程的逻辑身份，由 `key + tenant` 唯一确定，不承载具体结构 |
| 流程版本 | Process Version (`pf_process_version`) | 流程定义下的一个不可变结构快照；`DRAFT` 可改，`PUBLISHED` 只读 |
| 流程模型 | Process Model (JSON) | 版本的图形与语义载体，含 `nodes / edges / variables / settings` |
| 流程实例 | Process Instance (`rt_process_instance`) | 一次流程运行，绑定某个具体版本，运行期不再变版本 |
| 令牌 | Token (`rt_token`) | 自研引擎的执行指针。图遍历的最小调度单元，一个实例可有多个活跃令牌 |
| 节点实例 | Node Instance / Activity Instance (`rt_node_instance`) | 令牌在某个节点上的一次执行记录（含重试次数、输入输出快照） |
| 人任务 | User Task (`rt_task`) | 需要人工办理的等待态节点产生的待办 |
| 自动化节点 | Automation Node | 无需人工的前述节点（HTTP/SQL/MQ/脚本/服务调用等） |
| 连接器 | Connector (`int_connector`) | 对某种外部能力的可配置封装（HTTP、SQL、MQ、脚本、gRPC…） |
| 连接器操作 | Connector Operation | 连接器下的一个具体动作（如 `POST /orders`），流程节点引用它 |
| 网关闭环 | Gateway Join | 并行/包容网关的汇聚语义，由令牌计数 + 汇聚条件决定 |
| 会签 / 或签 | Multi-Instance | 多人任务：`ALL`（会签，全办完才推进）/ `ANY`（或签，一人办完即推进）/ `PERCENT` |
| 加签 | Add Sign | 在既有会签基础上追加办理人：前加签（自己之前）、后加签（自己之后） |
| 转办 / 委托 | Transfer / Delegate | 转办=彻底移交；委托=办理后回退给委托人确认 |
| 撤回 | Withdraw | 发起人或在办人回收已推进但下游未办结的任务 |
| 补偿 | Compensation | Saga 式反向操作，撤销已成功执行的前序自动化节点 |
| 事件订阅 | Event Subscription | 流程实例对 message / signal / timer 的等待登记 |
| 故障事件 | Incident (`rt_incident`) | 节点重试耗尽或不可恢复的业务/技术异常，需人工介入的记录 |
| 触发作业 | Scheduler Job (`sch_job`) | 由 cron / 固定频率 / 一次性触发的调度任务，可触发流程实例或调用连接器 |
| 租户 | Tenant | 逻辑隔离单元；一个租户 = 一套独立的流程空间、用户与数据视图 |
| 命令 | Command | 引擎内所有状态变更的统一封装（借鉴 Flowable），保证事务边界与可重放 |
| 发件箱 | Outbox | 本地事务内写事件表、事务提交后投递 MQ 的最终一致方案 |

- ❌ **Seata / 分布式事务框架**：跨服务一致性一律走「本地事务 + Outbox + 幂等消费 + 补偿」。
- ❌ Flowable / Camunda / Activiti 作为执行内核（仅保留导入 BPMN 2.0 XML 的能力）。

- ❌ 服务网格（Istio）与 Kubernetes Operator——v1.0 交付 Docker Compose + K8s Helm Chart。

## 3. 服务拆分与职责边界

原则：**按业务能力垂直切分，一个服务一个库，禁止跨库 JOIN**；跨服务只读数据一律「Feign + 本地冗余快照」，不做分布式事务。

| # | 服务 | 端口(建议) | 独立库 | 核心职责 |
| --- | --- | --- | --- | --- |
| 1 | `process-gateway` | 8080 | 无 | 统一入口、JWT 校验、路由、限流熔断、CORS、灰度 |
| 2 | `process-iam` | 8081 | `pe_iam` | 租户、用户、部门、角色、权限、菜单、用户组、登录认证、数据权限 |
| 3 | `process-design` | 8082 | `pe_design` | 流程定义/版本、模型校验、发布/下线、分类、导入导出、模板、表单定义与版本 |
| 4 | `process-engine` | 8083 | `pe_engine` | **执行内核**：实例、令牌、节点、变量、网关、人任务、定时器、事件订阅、故障、补偿、连接器执行 |
| 5 | `process-scheduler` | 8084 | `pe_scheduler` | cron/频率调度、触发流程实例或连接器、misfire 策略、执行记录、分布式抢占 |
| 6 | `process-integration` | 8085 | `pe_integration` | 连接器与操作定义、数据源、凭证管理（加密）、连通性测试、调用统计 |
| 7 | `process-notify` | 8086 | `pe_notify` | 消息模板、渠道配置、站内信/邮件/短信/Webhook（钉钉、企微、飞书）、重试 |
| 8 | `process-trace` | 8087 | `pe_trace` + ClickHouse | 操作审计日志、执行轨迹检索、统计聚合、实时推送（WS/SSE） |

**归属裁决（避免扯皮）**：

- **人任务属于 `process-engine`**，不单独拆 `task-service`。理由：人任务是引擎的 wait state，拆出去会把引擎状态机切成分布式状态机，收益远小于成本。若未来待办 QPS 独立成为瓶颈，再把 `rt_task` 读模型投影为只读的 `process-task-query` 服务。
- **连接器「定义/配置/凭证」在 `process-integration`，连接器「执行」在 `process-engine` 内嵌 SDK 完成**。理由：节点执行走网络跳转会给每条编排链路加一跳 RPC，且故障面扩大。引擎通过本地缓存 + 定时刷新获取连接器元数据。
- **表单定义在 `process-design`**（与流程版本同生命周期），表单**数据**落在 `rt_variable` / `rt_task.form_data_json`，表单**渲染**在前端 `@pe/form-renderer`。
- **`process-trace` 只做只读检索与推送，不写业务库**；引擎与各服务通过 MQ 单向投递轨迹事件。

### 3.1 服务内部模块划分（以 engine 为例）

```
process-engine
├── engine-api            # 对外 DTO / Feign 契约（被其他服务依赖）
├── engine-model          # 流程模型 POJO、节点类型枚举、解析器
├── engine-core           # 命令总线、令牌调度、网关算法、表达式、SPI 定义
├── engine-runtime        # 各节点行为实现（NodeBehavior）、定时器、事件、补偿
├── engine-task           # 人任务：候选人解析、认领、加签、转办、会签
├── engine-connector-sdk  # 连接器执行 SDK（HTTP/SQL/MQ/脚本），可被 worker 单独打包
├── engine-persistence    # Mapper / DO / 缓存
├── engine-worker         # 独立可部署的异步执行进程（消费 MQ 指令）
└── engine-boot           # Spring Boot 启动模块（同步 API 形态）
```

### 5.1 节点类型全集（`NodeType` 枚举，v1.0 冻结）

| 分组 | 节点类型 | 行为要点 |
| --- | --- | --- |
| 事件 | `START_EVENT` | 支持「表单发起 / API 发起 / 定时发起 / 消息发起」 |
| 事件 | `END_EVENT` | 结束当前令牌；无活跃令牌时实例完成 |
| 事件 | `TERMINATE_END_EVENT` | 终止整个实例 |
| 事件 | `TIMER_CATCH_EVENT` | 等待到期；写入 `rt_timer_job` |
| 事件 | `MESSAGE_CATCH_EVENT` / `SIGNAL_CATCH_EVENT` | 等待外部消息/广播信号 |
| 事件 | `ERROR_CATCH_EVENT` | 捕获子流程抛出的错误 |
| 边界 | `TIMER_BOUNDARY_EVENT` / `ERROR_BOUNDARY_EVENT` / `MESSAGE_BOUNDARY_EVENT` | 挂载在活动上，触发时打断或非打断 |
| 自动化 | `SERVICE_TASK` | 通用服务任务，绑定连接器操作或 Spring Bean |
| 自动化 | `HTTP_TASK` / `SQL_TASK` / `MQ_PRODUCE_TASK` / `SCRIPT_TASK` / `GRPC_TASK` | 连接器类节点，异步执行 + 回调恢复令牌 |
| 自动化 | `DELAY_TASK` | 延时（写入定时器，非阻塞） |
| 自动化 | `LOOP_TASK` | 集合遍历 / 次数循环，多实例令牌 |
| 自动化 | `SUB_PROCESS` / `CALL_ACTIVITY` | 内嵌子流程 / 调用其他流程定义（同步或异步） |
| 自动化 | `COMPENSATION_HANDLER` | 补偿处理器，被 `COMPENSATION_BOUNDARY` 触发 |
| 人工 | `USER_TASK` | 单选/会签/或签/比例签；候选人策略见 5.2 |
| 网关 | `EXCLUSIVE_GATEWAY` | 条件优先级 + 默认流，单令牌通过 |
| 网关 | `PARALLEL_GATEWAY` | fork/join，join 等待全部到达 |
| 网关 | `INCLUSIVE_GATEWAY` | 多条件分支，join 等待实际激活分支 |
| 网关 | `EVENT_GATEWAY` | 后接多个捕获事件的竞争等待，先到先得并取消其余 |

### 5.2 候选人策略（`assigneeStrategy`）

`USER`（指定人）/ `ROLE`（角色）/ `DEPT`（部门，含 `deptRecursive`）/ `USER_GROUP`（用户组）/ `EXPRESSION`（Aviator 表达式，返回用户 ID 列表）/ `INITIATOR`（发起人）/ `INITIATOR_LEADER`（发起人直属上级）/ `FORM_FIELD`（表单字段值）/ `PREV_APPROVER`（上一节点办理人）。

去重与自动跳过规则：`autoSkipSameApprover`（同一审批人连续节点自动通过）、`dedupe`（候选人去重）、`emptyStrategy`（`ADMIN` 兜底 / `SKIP` 自动通过 / `EXCEPTION` 抛故障）。

### 5.3 引擎扩展点（Java SPI + Spring Bean 双重注册）

| SPI | 职责 |
| --- | --- |
| `NodeBehavior` | 节点执行行为，`nodeType()` 匹配，`execute(ExecutionContext)` |
| `ExpressionEvaluator` | 表达式求值（默认 Aviator） |
| `AssigneeResolver` | 候选人解析策略扩展 |
| `ConnectorExecutor` | 连接器类型执行扩展 |
| `TaskListener` / `ExecutionListener` / `ProcessListener` | 生命周期监听（创建/指派/完成/撤回） |
| `VariableSerializer` | 变量序列化（大对象外置策略） |
| `MisfirePolicy` | 调度 misfire 策略扩展 |
| `NotifyProvider` | 通知渠道扩展 |

## 6. 全局规范（强制）

### 6.1 命名

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| Maven 模块 | `process-{服务}` / `{服务}-{内层模块}` | `process-engine`, `engine-core` |
| Java 包 | `com.pe.{服务}.{层次}` | `com.pe.engine.runtime` |
| 类 | 分层后缀：`Controller/Service/ServiceImpl/Mapper/DO/DTO/VO/Convert/Config/Handler/Command/Behavior` | `ProcessInstanceController` |
| 表 | 小写下划线，`{域前缀}_{名词}` | `rt_process_instance` |
| 字段 | 小写下划线 | `initiator_id` |
| 接口路径 | `/api/{服务短名}/v{版本}/{资源复数}` | `/api/engine/v1/instances` |
| 前端组件 | `PascalCase.vue` | `FlowDesigner.vue` |
| 前端包 | `@pe/{包名}` | `@pe/flow-designer` |
| 常量/枚举 | 枚举值 `UPPER_SNAKE` | `USER_TASK` |

### 6.2 主键与 ID

- 所有表主键 `id BIGINT UNSIGNED`，**雪花算法**生成（`workerId` 由 Nacos 分配，避免时钟回拨）。
- 对外 JSON 中**所有 Long 型 ID 序列化为字符串**（`@JsonSerialize(using = ToStringSerializer.class)` 或全局 Jackson 配置），防止 JS 精度丢失。
- 业务编号另设 `*_no` 列（如 `instance_no`），格式 `{前缀}{yyyyMMdd}{8位序列}`，用于人机交互与幂等键。

### 6.3 多租户

- **逻辑隔离为默认**：所有业务表带 `tenant_id`，MyBatis-Plus `TenantLineInnerInterceptor` 自动注入与拦截；网关解析 JWT 中的 `tenantId` 写入 `TenantContext`。
- 平台级表（`sys_tenant`）与跨租户统计走 `@IgnoreTenant` 白名单。
- 保留**物理隔离升级路径**：`sys_tenant.isolation_mode = LOGIC | SCHEMA | DATABASE`，DAO 层通过动态数据源路由支持，v1.0 只实现 `LOGIC`。
- 租户级资源配额（实例数、并发任务数、调用量）在 `sys_tenant` 扩展配置中限流。

### 6.4 时间与并发

- 存储统一 `DATETIME(3)`，UTC+8 入库；Java 侧 `LocalDateTime`；前端展示按浏览器时区转换。
- 所有关系表 `create_time` / `update_time` 由 MyBatis-Plus 自动填充。
- **乐观锁**：`rt_process_instance` / `rt_token` / `rt_task` / `rt_node_instance` 带 `version` 列，`@Version` 生效；冲突时抛出可重试异常并由引擎重投。
- **实例级串行**：同一 `instance_id` 的推进必须串行。锁策略：Redis 分布式锁 `engine:inst:{instanceId}`（Redisson，看门狗续期）+ DB 行锁双保险，锁超时 30s，获取失败则消息重投退避。

### 6.5 公共列（所有业务表强制）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `BIGINT UNSIGNED NOT NULL` | 雪花主键 |
| `tenant_id` | `BIGINT UNSIGNED NOT NULL DEFAULT 0` | 租户（平台表为 0） |
| `create_by` | `BIGINT UNSIGNED NULL` | 创建人 |
| `create_time` | `DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3)` | 创建时间 |
| `update_by` | `BIGINT UNSIGNED NULL` | 更新人 |
| `update_time` | `DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3)` | 更新时间 |
| `deleted` | `TINYINT NOT NULL DEFAULT 0` | 逻辑删除（0 未删 / 1 已删） |
| `version` | `INT NOT NULL DEFAULT 0` | 乐观锁（仅并发写表需要） |

**乐观锁列命名例外（v1.0.2 增补，唯一例外）**：当表的**业务列已占用 `version`**（如 `pf_process_version.version` 表示流程版本号、`pf_form_version.version` 表示表单版本号、`rt_process_instance.version` 表示绑定的流程版本、`int_connector.version` 表示连接器实现版本）时，乐观锁列命名为 **`version_lock`**（类型、语义、用法与 `version` 完全一致，MyBatis-Plus `@Version` 映射到该列）。适用于 `pf_process_version`、`pf_form_version`、`rt_process_instance`、`int_connector` 共 4 张表。**业务语义优先于列名统一**：`version` 永远表示业务版本号，`version_lock` 永远表示乐观锁，禁止在同一张表中让 `version` 兼任乐观锁。

表默认：`ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci ROW_FORMAT=DYNAMIC`。

### 6.6 统一响应与错误码

```jsonc
// 成功
{ "code": "0", "message": "ok", "data": { }, "traceId": "3f9c1a..." }
// 失败（HTTP 状态码同时保持语义，如 400/403/404/409/500）
{ "code": "ENGINE_40001", "message": "流程实例不存在或已结束", "data": null, "traceId": "3f9c1a..." }
```

- `code` 为字符串，格式 `{DOMAIN}_{5位数字}`；`DOMAIN ∈ {COMMON, AUTH, IAM, DESIGN, FORM, ENGINE, TASK, SCHED, INTEG, NOTIFY, TRACE}`。
- 数字段规则：`1xxxx` 参数/校验，`2xxxx` 权限/租户，`3xxxx` 业务状态冲突，`4xxxx` 资源不存在，`5xxxx` 系统/依赖故障。
- 国际化：`message` 由服务端按 `Accept-Language` 从 `messages_{locale}.properties` 渲染，键名与 `code` 一致。

### 6.7 分页与查询

- 统一入参 `pageNum`（从 1 开始）、`pageSize`（默认 20，最大 200）、`orderBy`、`orderDirection`。
- 统一出参 `{ "pageNum": 1, "pageSize": 20, "total": 137, "records": [] }`。
- 大数据量列表（实例、任务、日志）禁止深分页：`pageNum * pageSize > 10000` 时强制走 `searchAfter`（游标 `lastId`）模式。

### 6.8 鉴权与安全

- 认证：JWT（RS256，Access Token 2h / Refresh Token 7d），Redis 维护黑名单与在线会话。
- 授权：RBAC（角色-权限）+ 数据权限（`data_scope`: ALL / DEPT_AND_CHILD / DEPT / SELF / CUSTOM）。
- 服务间：内部调用携带 `X-Internal-Token`（网关签发，服务侧校验），外部只经网关。
- 凭证加密：`int_credential.content_cipher` / `int_datasource.password_cipher` 用 AES-256-GCM，密钥经 KMS/环境变量注入，**禁止硬编码与明文落库**。
- 审计：所有写操作与关键读操作投递 `tr_oper_log`，保留 ≥ 180 天。
- 防护：网关级限流（IP/用户/租户三维）、参数校验、MyBatis 预编译、脚本沙箱（GraalVM JS 禁 IO/线程/反射，超时 3s 强制中断）、SSRF 白名单（HTTP 连接器目标域名需在 `int_connector` 中配置）。

### 6.9 日志与可观测

- 每层强制 MDC：`traceId`（OTel） / `tenantId` / `userId` / `instanceId`（引擎链路） / `nodeInstanceId`。
- 日志格式：`时间 级别 [traceId][tenantId] 线程 类 - 消息`，JSON 格式输出到 stdout（容器采集）。
- 指标：HTTP（QPS/延迟/错误率）、引擎（实例启动数、令牌推进耗时、任务积压、定时器延迟、incident 数）、MQ（堆积）、连接池。
- 健康检查：`/actuator/health`（liveness/readiness 分离），就绪探针检查 DB/Redis/MQ。

### 6.10 幂等与一致性

- **写接口幂等**：外部写接口要求 `Idempotency-Key` 头，落 `rt_idempotent`；内部消费幂等键 = `{instanceId}:{nodeInstanceId}:{attempt}`。
- **跨服务一致性**：本地事务内写 `rt_outbox`，事务提交后由中继任务投递 MQ（至少一次）；消费端幂等表去重（最终一致）。
- **MQ 约定**：Topic 命名 `PE_{DOMAIN}_{EVENT}`，如 `PE_ENGINE_NODE_COMPLETED`；消息体含 `eventId / tenantId / occurredAt / traceId / payload`；消费失败重试 3 次后入死信 Topic `PE_DLQ_{原Topic}`。

## 7. 非功能性基线指标

| 指标 | 目标 |
| --- | --- |
| 实例启动延迟 | P99 < 300ms（同步推进到第一个等待态） |
| 大列表查询（实例/任务） | P99 < 200ms（1000 万实例量级，走覆盖索引） |
| 自动化节点吞吐 | 单引擎 Worker ≥ 500 TPS，集群线性扩展；平台整体 ≥ 2000 TPS |
| 并行运行实例容量 | ≥ 100 万活跃实例，≥ 5000 万历史实例 |
| 定时器精度 | 到期偏差 P99 < 2s（10 万级待触发定时器） |
| 可用性 | 99.95%（核心引擎与网关），无单点 |
| 恢复能力 | 单节点宕机，运行中实例 60s 内被其他节点接管并继续推进 |
| 数据一致性 | 实例状态最终一致，不允许出现「有活跃令牌但无待办/无定时器」的悬挂态（由对账任务 5 分钟巡检告警） |
| 安全 | 通过越权、注入、脚本逃逸基线测试；无明文凭证 |
| 可观测 | 全链路 traceId 贯通；核心指标大盘齐备；告警规则覆盖 P0/P1 |
